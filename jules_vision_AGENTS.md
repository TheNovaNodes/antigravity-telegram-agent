# Инструкции для ИИ-агентов (Jules' Vision)

Привет, будущий ИИ-агент! Я проанализировал этот репозиторий и собрал для тебя свод правил и рекомендаций, которые помогут работать эффективно, безопасно и в соответствии с архитектурой проекта.

## 1. Стек и зависимости
Проект написан на Go и представляет собой высокопроизводительное ядро для ботов Telegram (Antigravity Telegram Agent).
- **Язык:** Go (версия 1.25.0, как указано в `go.mod`).
- **База данных:** SQLite3 (`github.com/mattn/go-sqlite3`).
- **Telegram API:** `github.com/go-telegram-bot-api/telegram-bot-api/v5`.
- **Внешние утилиты:** Antigravity CLI бинарник (`agy`), ожидается в `$PATH` или по пути `/root/.local/bin/agy`.
- **Остальные библиотеки:** `github.com/google/uuid`, `golang.org/x/net`.

## 2. Команды верификации
Перед любым коммитом и открытием Pull Request **обязательно** выполняй следующие команды:
- Форматирование кода: `go fmt ./...`
- Статический анализ (линтер): `go vet ./...`
- Запуск тестов (с проверкой покрытия): `go test -v -cover ./...`
- Сборка бинарника: `go build -o new_engine .`

Убедись, что все команды завершаются без ошибок.

## 3. Архитектурные особенности и правила кодинга
- **ПРАВИЛА КРОВИ (Strict Git Flow):** Прямые коммиты в `master` запрещены. Вся работа ведется в отдельных ветках (например, `feature/...` или `fix/...`). Изменения вливаются только через Pull Request.
- **Изолированные песочницы (CWD Sandboxing):** Каждый бот работает в собственной директории на хосте (`/root/.agents/<botName>`). Команды ОС (`exec.Cmd`) строго привязываются к этой директории через `Cmd.Dir`. Не пытайся записывать или читать файлы вне этой "личной" директории.
- **Асинхронный троттлинг:** Для предотвращения блокировок (HTTP `429 Too Many Requests`) от Telegram API, чтение потока вывода (`stdout`) ботов и отправка сообщений разделены. Чанки накапливаются и отправляются асинхронно. Учитывай это при изменении логики отправки.
- **Хранение состояния:** Сессии пользователей для каждого бота хранятся в отдельных SQLite базах данных (например, `sessions_<botName>.db`).
- **Конфигурация (ENV):** Для работы требуется файл `.env` с переменными `BOT_TOKENS`, `ALLOWED_ADMIN_IDS` и, опционально, `ELEVENLABS_API_KEY`.

## 4. Советы для будущих ИИ-агентов
- **Не ломай песочницу:** Если тебе нужно модифицировать работу с файловой системой для бота, всегда убеждайся, что пути остаются в рамках `/root/.agents/<botName>`.
- **Пиши тесты:** Покрытие кода на старте было в районе 30%. При добавлении нового функционала или исправлении багов всегда добавляй юнит-тесты в соответствующие файлы (например, `_test.go`).
- **Будь осторожен с `stdout`:** Проект решает проблему переполнения буфера ОС. Не добавляй синхронные блокирующие вызовы в циклы чтения потоков.
- **Соблюдай CI/CD:** После открытия PR подожди результатов автоматических проверок (GitHub Actions: `ci.yml`). Если что-то упало — исправь в той же ветке и запуш заново.
- **Изучи скрипты деплоя:** В репозитории есть `deploy.sh` и `deploy_all.sh`. При изменении процесса сборки, не забудь проверить, не сломаются ли эти shell-скрипты.
