# Инструкции для ИИ-агентов (AGENTS.md) — Antigravity Telegram Agent

Добро пожаловать в репозиторий `antigravity-go-tg-bot-agent`. Этот документ содержит ключевую информацию для ИИ-агентов, работающих с данным кодом. Соблюдение этих правил обеспечит стабильность кодовой базы и успешное прохождение CI.

## 1. Стек и зависимости
* **Язык:** Go (версия 1.22 и выше, целевая в `go.mod` обычно указывает на текущую версию, ожидается >= 1.22).
* **База данных:** SQLite3 (используется драйвер `github.com/mattn/go-sqlite3` через CGO).
* **Ключевые библиотеки:**
  * `github.com/go-telegram-bot-api/telegram-bot-api/v5` — взаимодействие с Telegram API (Long-Polling).
  * `github.com/google/uuid` — генерация идентификаторов сессий.
* **Внешние зависимости:** Для локального запуска и полного функционирования необходим бинарник Antigravity CLI (`agy`), который должен быть доступен в `PATH` или по пути `/root/.local/bin/agy`.

## 2. Команды верификации
Перед любым коммитом **обязательно** выполни следующие проверки. Если они не проходят, исправь код!

* **Форматирование кода:**
  ```bash
  go fmt ./...
  ```
* **Линтинг (статический анализ):**
  ```bash
  go vet ./...
  ```
* **Сборка проекта:**
  ```bash
  go build -o new_engine .
  ```
* **Запуск тестов с покрытием:**
  ```bash
  go test -v -cover ./...
  ```
*(Обрати внимание на покрытие: новые фичи должны сопровождаться юнит-тестами, чтобы покрытие не падало. Сейчас целевой ориентир ~30%+, старайся его увеличивать).*

## 3. Архитектурные особенности и правила кодинга

* **Строгий Git Flow (ПРАВИЛА КРОВИ):**
  Запрещены прямые коммиты в `master`. Вся работа должна вестись в feature- или fix-ветках с последующим созданием Pull Request (PR).
* **Среда выполнения и изоляция (Sandboxing):**
  Каждый агент работает в своей изолированной среде (директории).
  * Путь рабочей области (Workspace) берется из SQLite: `/root/.agents/<botName>`.
  * При создании `os/exec.Cmd` (запуск `agy`) **обязательно** нужно задавать `Cmd.Dir` равным этому Workspace. Это предотвращает взаимное влияние ботов.
* **Асинхронность и обход ограничений Telegram API (Deadlock Protection):**
  Нельзя синхронно отправлять данные в Telegram прямо из цикла чтения `stdout`.
  * Чтение `stdout` (JSONL stream) происходит асинхронно в горутине.
  * Буферизованные данные должны отправляться (flush) специальным `throttler`-ом каждые 100 мс. Это спасает от ошибки `429 Too Many Requests` и переполнения OS pipe buffers.
* **Отсутствие хардкода:**
  Токены (`BOT_TOKENS`), ID администраторов (`ALLOWED_ADMIN_IDS`) и другие секреты должны браться **исключительно** из `.env` файла или переменных окружения. Никакого хардкода секретов в исходниках!
* **Управление сессиями (Concurrency):**
  Используется глобальный map сессий (`globalSessions`) с мьютексом (`sessionMu`). Обязательно лочь/анлочь мьютексы (`mu.Lock()` / `mu.Unlock()`) при доступе к shared state (состоянию сессии), чтобы избежать race conditions.

## 4. Советы для будущих ИИ-агентов (Мое видение)

1. **Не ломай пайпы (Pipes):** Если ты модифицируешь логику чтения I/O (файлы вроде `agysessionsstarter.go`), убедись, что каналы связи с процессом закрываются корректно (defer), иначе останутся zombie-процессы или произойдут утечки горутин.
2. **Пиши тесты:** В проекте уже есть файлы тестов (например, `agysessionsstarter_test.go`, `formatters_test.go`, `tts_test.go`). Прежде чем изменять логику форматирования Markdown (`formatters.go`), добавь тест на свой кейс. Telegram очень чувствителен к неэкранированному MarkdownV2!
3. **Локальная песочница:** При отладке проблем, помни, что база SQLite генерируется на лету (`sessions_<botName>.db`). Если что-то идет не так с сессиями, иногда проще удалить базу и начать заново, чем писать сложные миграции для локального дева.
4. **Осторожно с CGO:** Так как используется драйвер `go-sqlite3`, компиляция требует CGO. Убедись, что в среде сборки (особенно в CI) установлен C compiler (gcc).
5. **Проверяй логи:** Если бот не стартует, проверь парсинг `.env`. Переменная `BOT_TOKENS` может содержать несколько токенов (ведь это единый движок для 8 ботов). Учитывай, что парсинг разделителей в `BOT_TOKENS` критически важен.
