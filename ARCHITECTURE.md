## 🏛️ 1. Обзор архитектуры системы

**DMagyBOT** представляет собой асинхронный адаптер-шлюз между пользователями Telegram и CLI-агентом **Google Antigravity (`agy`)**. Архитектура построена на принципах полной изоляции клиентских сессий, эмуляции виртуального терминала через PTY и двухслойной интеграции по протоколу **Model Context Protocol (MCP)**.

## 🔧 2. Ключевые архитектурные компоненты

### 2.1. PTY-Терминальный слой & Hot Reload (`src/cli_runner.py`)
- **Проблема**: Стандартный subprocess застревает на управляющих последовательностях ANSI и интерактивных промптах CLI.
- **Решение**: Процесс `agy` запускается через `pexpect.spawn` в контексте псевдо-терминала PTY (`TERM=xterm`).
- **Рендеринг вывода & Оптимизация CPU**: Вывод PTY транслируется в виртуальный терминал **`pyte.Screen(120, 60)`** с помощью `pyte.ByteStream`. Для устранения 100% CPU busy-loop нагрузки при ожидании вывода от LLM в цикл чтения `read_nonblocking` добавлен асинхронный микро-таймаут (`asyncio.sleep(0.05)` при `timeout=0.1`), обеспечивающий мгновенный отклик при нулевой нагрузке на процессор.
- **Автоматический Hot Reload авторизации & OAuth Userinfo (`get_auth_state_signature`)**: Мониторинг сигнатуры токенов в `~/.gemini/antigravity-cli/antigravity-oauth-token`, `settings.json`, `jetski_state.pbtxt` и системных логах `cli.log`. Текущий пользователь и e-mail извлекаются нативно через эндпоинт `https://www.googleapis.com/oauth2/v3/userinfo` с полным кэшированием. При смене аккаунта через `agy auth login` PTY-процесс принудительно убивается сигналом `SIGKILL` (signal 9) и спавнится заново с аккаунтом без ручных действий.
- **Интеграция квот моделей (`/usage`)**: Прямой перехват вывода команды `/usage` из CLI с форматированием в Rich Text HTML (прогресс-бары остатка квот и отсчет времени до сброса лимита).
- **Переименование и история сессий (`/rename` & `/resume`)**: Позволяет возобновлять и изменять названия сессий напрямую в SQLite-базе CLI `conversation_summaries.db`.

### 2.2. Форматирование Dyslexia-Friendly & Очистка Текста (`src/formatters.py`)
- **Paragraph Unwrapping & Whitespace**: Автоматическая склейка рваных 120-символьных строк терминала в плавные естественные предложения с двойным отступом (`\n\n`) между абзацами для облегчения восприятия.
- **Telegram Rich Text (HTML)**: Полная конвертация Markdown в Telegram-совместимый HTML:
  - Заголовки `#` -> `<b><u>HEADER</u></b>`
  - Код и блоки кода -> `<code>...</code>` и `<pre><code class="language-...">...</code></pre>`
  - Жирный/курсив -> `<b>...</b>`, `<i>...</i>`
  - Цитаты -> `<blockquote>...</blockquote>`
  - Ссылки -> `<a href="...">...</a>`
- **Mono Tech-Term Highlighting**: Автоматическое оборачивание изолированных латинских терминов, названий модулей и путей к файлам (например, `src/db.py`, `SearXNG`) в моноширинный шрифт `<code>`, снижающий когнитивную нагрузку для дислексиков.
- **TUI Noise Filter**: Полная фильтрация ASCII-арта (`▄▀▀`), CLI-заголовков (`Antigravity CLI`), эхо-команд (`> ...`) и системных путей.
- **Error Interception**: Перехват и трансформация сырых системных ошибок (`Eligibility Check`, `Quota Exceeded`) в структурированные пошаговые гайды на русском языке.

### 2.3. Менеджер сессий и Idle TTL (`src/session_manager.py`)
- Каждый `chat_id` получает отдельный изолированный экспорт сессии `AgySession`.
- **Фоновая очистка ресурсов**: Каждые 5 минут запускается асинхронный таск `start_cleanup_loop()`, закрывающий PTY-процессы сессий, неактивных более 30 минут.

### 2.4. Персистентность состояний (`src/db.py`)
- База данных SQLite (`data/dmagybot.db`) автоматически сохраняет параметры пользователя:
  - Выбранная модель (`model_name`)
  - Глубина рассуждений (`effort`)
  - Режим работы (`mode`)
- При перезапуске сервиса состояния сессий бесшовно восстанавливаются без потери пользовательских настроек.

### 2.5. Двухуровневая MCP-интеграция (`src/mcp_config.py`)
- **Data Plane (Операционный)**: Автоматическая трансляция эндпоинтов `nova-anythingllm-mcp`, `nova-searxng-mcp` и `nextcloud-mcp` в вызовы `agy`.
- **Control Plane (Изолированный)**: Административные функции разделены для обеспечения информационной безопасности.

### 2.6. Аудит операций (`src/audit.py`)
- Фиксация всех запросов в `logs/audit.log` в формате JSON Lines:
  - `timestamp`, `user_id`, `chat_id`, `model_name`, `effort`, `mode`, `prompt`, `response_length`.

## 🧪 3. Гарантии надежности и тестирование

Пакет юнит-тестов в директории `tests/` полностью покрывает логику работы бота:
- `test_config.py` — проверка конфигурации и фильтров авторизации.
- `test_cli_runner.py` — жизненный цикл PTY-процессов и парсинг экранов pyte.
- `test_session_manager.py` — изоляция сессий и Idle-очистка.
- `test_db_persistence.py` — CRUD операции SQLite.
- `test_handlers.py` — маршрутизация команд и инлайн-клавиатуры.
- `test_chunking.py` — алгоритм разбиения сообщений > 4000 символов.
- `test_mcp.py` — корректность конфигуратора MCP.

Команда запуска тестирования:
```bash
PYTHONPATH=. pytest
```

## 🔧 9. Автоматический установщик (`setup.sh`)

Универсальный скрипт установки, поддерживающий два режима:

**Интерактивный режим** (без аргументов):
```bash
sudo ./setup.sh
```
Скрипт последовательно запрашивает Telegram Bot Token и User ID.

**Режим автоматизации** (с аргументами):
```bash
sudo ./setup.sh --token="TOKEN" --user-id="123456789"
```

### Что делает `setup.sh`:

| Шаг | Действие |
|-----|----------|
| 1 | Проверяет наличие Python 3.10+, `agy` CLI и авторизацию |
| 2 | Запрашивает (или принимает через аргументы) токен бота и User ID |
| 3 | Генерирует `.env` с правильным `AGY_BINARY_PATH` (автоопределение) |
| 4 | Создает `.venv` и устанавливает все Python-зависимости |
| 5 | Генерирует `dmagybot.service` с корректными путями для текущего сервера |
| 6 | Регистрирует, включает и запускает systemd-сервис |

### Ключевой принцип:
Файл `dmagybot.service` **генерируется динамически** при установке — пути `WorkingDirectory`, `ExecStart` и `User` подставляются автоматически из текущего окружения. Это обеспечивает работу бота на любом сервере без ручной правки конфигурации.
